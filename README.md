# 企业内部知识问答与制度助手

面向企业内部的制度与流程问答原型：员工用自然语言提问，系统**只在已收录资料中检索证据**并标注来源；资料不足时明确说明，不编造。

- 形态：单文件前端应用（`index.html`），无构建步骤，数据存浏览器 IndexedDB；另附一个**零依赖 Node 服务端参考实现**（`server/`），用于把权限与审计真正搬到服务端
- 定位：可离线运行的**证据检索型**问答原型，用于验证「有据可查 + 不编造 + 权限可见范围」这条链路
- 两种回答模式：**证据摘录**（默认，纯本地、不联网）与**生成式回答**（可选，接入任意 OpenAI 兼容接口，仍只依据检索到的资料作答并强制标注来源）
- 权限与审计：纯本地模式下由显式策略表 `ACCESS_POLICY` 判定、审计存本机 IndexedDB；**服务端模式下**改为真实登录 + 服务端逐请求校验 + 追加式审计（详见下文与 [`docs/服务端说明.md`](docs/服务端说明.md)）
- 文档导入：TXT / MD / CSV / JSON / HTML 直接读取；**DOCX / PDF 纯前端零依赖解析**（DOCX 读 ZIP 中央目录取 `word/document.xml`；PDF 解 FlateDecode 流 + ToUnicode CMap 取文本，扫描件会被识别并拒绝）
- 当前状态：功能闭环已完成；离线评测 **118/118**、生成层 11/11、权限与审计 10/10、文档解析 12/12、模型列表与重排 24/24、回答展示 22/22、文档管理 35/35、**服务端模式 54/54**、**使用者体验 29/29** 通过（见下文）

## 快速开始

方式一，直接双击 `index.html`（Chrome / Edge）——纯本地模式，不需要任何服务。

方式二，起一个本地静态服务（推荐，IndexedDB 在 http 源下行为更稳定）：

```bash
cd enterprise-knowledge-assistant   # 换成你 clone 后的目录
python -m http.server 8765 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8765
```

方式三，**启动服务端**（真实身份 + 服务端权限 + 追加式审计）：

```bash
node server/server.mjs
# 浏览器打开 http://127.0.0.1:8787
# 「资料与权限」页 → 服务端模式 → 账号 hr / 口令 demo1234
```

首次打开会自动载入 5 份虚构演示制度。纯本地模式下顶部「演示身份」可切换 员工 / 人事 / 主管 / 管理员；服务端模式下身份由登录决定，下拉会被锁定。

## 功能

| 模块 | 能力 |
| --- | --- |
| 知识问答 | 自然语言提问 → 返回原文证据 + 来源文档 + 匹配度；无依据时明确拒答；答案可点击放大阅读 |
| 使用体验 | 首次上手引导（可关闭、刷新后不再打扰）；**最近提问历史**（可点重问、可清空）；检索与生成阶段**可见加载态**（按钮 loading + 骨架屏 + 阶段文案）；**一键复制**答案 / 证据原文 / 文档全文 / 放大内容；拒答时给出**可点的替代建议**（取当前身份可见的文档标题与分类）；搜索框空输入禁用查询、清除按钮、`/` 快捷键聚焦、Enter 提交；答案区 `aria-live` + `aria-busy` 供屏幕阅读器播报 |
| 生成式回答（可选） | 配置 OpenAI 兼容接口后，由模型基于检索到的资料生成回答并标注来源；**无依据不调用模型**；越界引用与未落地数值会被标记；调用失败自动回退为证据摘录。回答**可点击放大**，放大视图上方是生成回答、下方逐条附**来源原文（逐字摘录）**，便于核对是否与文档一致；也可一键「查看原文证据」切换到逐字原文 |
| 可用模型列表 | 一键 `GET {baseUrl}/models` 拉取接口可用模型，展示模型名与关键属性（归属方、创建时间、上下文长度、最大输出、参数规模、量化格式等）；点击即填入模型名；兼容 OpenAI / Ollama / 纯数组等格式；拉取失败给出可读提示并保留手动填写 |
| 检索重排（可选） | 开关控制：开启后先让模型按相关度对候选片段重排再作答，提升长文档下的 Top-1 精度；重排接口不可用时**静默回退原始排序**，不影响作答 |
| 编号定位 | 资料里带 `1.1 / 1.2`、`【追问1】/【问题2】` 等编号时，按序号精确取答案，不越界到兄弟小节 |
| 知识文档 | 导入（TXT / MD / CSV / JSON / HTML / **DOCX / PDF**）、编辑、启停、移除；Markdown 标题按层级渲染；DOCX 标题样式还原为 Markdown 标题层级 |
| 资料与权限 | 纯本地模式：演示身份切换，可见范围由 `ACCESS_POLICY` 策略表统一判定，无权文档在列表中标记、打开时被拒；服务端模式：文档在出网前按身份过滤，越权文档根本不下发 |
| 服务端模式（可选） | 连接 `server/` 参考实现后：真实登录（scrypt 口令哈希 + HMAC token）、服务端逐请求权限校验（越权 403）、写入侧 RBAC（仅管理员可维护文档）、追加式审计日志 + 哈希链完整性校验 |
| 操作审计 | 提问、拒答、安全拦截、查看文档、导入 / 编辑 / 启停 / 移除、备份导出、模型配置、身份切换、复制内容均留痕（时间 / 身份 / 动作 / 对象 / 结果）；汇总被拒绝操作数；**可按结果 / 身份 / 操作类型筛选**；可导出 JSON、可清空（清空动作本身也留痕）。服务端模式下另有服务端权威日志（append-only，客户端无法修改或删除） |
| 数据本地化 | 全部数据存本机 IndexedDB（`documents` / `feedback` / `audit`）；支持 JSON 备份导出；反馈与审计记录保存在本机 |

## 架构

```
index.html（单文件）
├── 视图层    四段式工作区：知识问答 / 知识文档 / 操作审计 / 资料与权限
├── 状态层    state = { docs, role, page, audit, answerZoomItems, llm, ... }
├── 存储层    IndexedDB: zhigui-local-knowledge（DB_VERSION 2）
│              ├── documents  知识文档（id / title / category / audience / status / body）
│              ├── feedback   问答反馈
│              └── audit      操作审计（at / role / action / target / detail / result）
│             localStorage: zhigui-llm-config（可选的模型服务配置）
├── 权限层    ACCESS_POLICY 策略表 → canAccess(role, doc) → authorize(doc, action)
│             检索入口与卡片渲染共用同一判定（visible 委托 canAccess）
├── 检索层    分块 → 打分（正文 + 标题权重）→ 阈值过滤 → 编号小节聚合 → 排序取前 N
├── 解析层    DOCX：ZIP 中央目录 → word/document.xml → 段落/标题样式 → Markdown
│             PDF：扫描 stream → FlateDecode → ToUnicode CMap → 文本操作符 → 可读率校验
├── 生成层    前置安全闸 → 组装上下文 → 流式调用 → 引用/数值校验 → 失败回退（可选）
│             ├── 模型列表  GET {baseUrl}/models → normalizeModelList → 展示 + 点击选用
│             └── 检索重排  候选编号 → 模型排序 → 解析顺序 → 失败静默回退
├── 审计层    recordAudit(action, {target, detail, result}) → 内存 + IndexedDB
│             服务端模式下同时上报 /api/events（授权相关动作由服务端自行记录）
└── 展示层    Markdown 清洗 → 层级渲染 → 证据卡片 + 来源 + 放大阅读
```

### 检索管线（一句话版）

1. **归一**：先把同义词变体替换为规范词（`口令`→`密码`、`薪水`→`工资`…，14 组），query 与分块同时归一
2. **分块**：优先按 Markdown 标题切分，记录每个分块「最近的带编号祖先小节」；无标题时按段落切分，识别 `【追问N】` 等问答分组
3. **打分**：中文 2-gram + 拉丁 token；先删疑问短语再删单字虚词，丢弃纯功能字 gram，再算 `coverage`（命中词占比），整句命中额外加权；**小节标题单独打一次分并按 0.5 权重并入总分**（标题命中比正文命中更能代表主题）
4. **过滤**：按查询长度分档设阈值（0.35 / 0.5 / 0.75）；明显弱于最佳命中的兄弟小节直接丢弃
5. **主题校验**：候选必须命中至少一个**主题词**——只命中「审批 / 流程 / 申请」这类通用词不算，避免答非所问
6. **聚合**：同一编号小节（如 `1.1`）下的正文、无编号子标题、`【追问N】` 合并为**一条完整答案**
7. **取用**：按文档去重、每文档最多 2 条、总计最多 5 条；排序依次比较「总分 → 标题覆盖度 → 正文覆盖度 → 长度」；常规查询展示前 3 条，**按序号定位展示全部**；无结果或最高匹配度过低时拒答

## 生成式回答（可选）

默认不联网。在「资料与权限 → 模型服务（可选）」填入任意 OpenAI 兼容的 Base URL 与模型名即可启用。

- **无依据不生成**：检索不到证据时直接拒答，**一次模型请求都不发**
- **只喂检索结果**：上下文只包含命中的编号小节原文，编号 `[1][2][3]` 与界面来源列表一一对应
- **强制标注来源**：系统提示词要求每条结论标 `[编号]`，回答后校验引用是否越界、是否有引用
- **数值落地校验**：回答里的金额 / 比例 / 天数等数值若在来源全文中找不到，标黄提醒人工复核
- **前置安全闸**：提示注入（「忽略以上指令…」）与批量导出意图（「列出全部文档原文」）在检索前即被拦截
- **失败自动回退**：网络异常 / HTTP 错误 / 空响应 → 同屏回退为证据摘录，系统不因模型不可用而瘫痪
- **结果可核对**：回答卡片整体可点击放大；放大视图上半部分是模型生成的回答，下半部分逐条列出**来源原文（逐字摘录，未经改写）**。另提供「查看原文证据」按钮，一键切换为完全逐字的原文模式
- **措辞对齐原文**：系统提示词要求材料名称、部门名、系统名、金额、天数、比例等必须照抄资料原文，只允许精简句式，不得改写或替换同义词

**可用模型列表**：在「模型名称」右侧点「拉取模型列表」，会请求 `GET {baseUrl}/models` 并把返回的模型渲染成可点选列表，每项展示模型名 + 关键属性（归属方、创建时间、上下文长度、最大输出、参数规模、量化格式等），点一下就填进「模型名称」。兼容 OpenAI（`{object,data[]}`）、Ollama（`{models[]}`，含 `details.parameter_size` / `size` / `format`）、`{result[]}` 与纯字符串数组；接口不提供 `/models` 或鉴权失败时给出可读提示，手动填写仍然可用。

**检索重排**：勾选「检索重排」后，检索到的候选片段会先发给模型按相关度排序，再进入作答环节。重排只影响**顺序**，不增删证据、不改变来源编号的对应关系；重排接口报错、超时或返回不可解析内容时**静默回退**为原始排序，用户侧无感。

密钥只写入本机 `localStorage`，不写进导出备份。协议、提示词、模型列表与重排细节见 [`docs/生成层说明.md`](docs/生成层说明.md)。

## 使用体验

功能齐了不等于好用。这一版按真实使用路径把「找到答案」这条主链路重走了一遍，把摩擦点逐条补上：

| 场景 | 原来的问题 | 现在的做法 |
| --- | --- | --- |
| 第一次打开 | 不知道该从哪开始 | 顶部三步上手引导，点 `×` 关闭后记进 `localStorage`，不再打扰 |
| 想回看问过什么 | 结果被下一次提问覆盖 | **最近提问**保留 8 条，点一下即重问，可一键清空 |
| 等生成式回答 | 只有一行小字，不知道要等多久 | 查询按钮进入 loading 态 + 结果区骨架屏 + 阶段文案（检索中 / 重排中 / 生成中） |
| 想复用答案 | 只能手动框选 | 证据模式复制「证据原文」、生成式复制「模型回答」、文档预览复制全文、放大弹窗复制内容 |
| 没找到答案 | 只提示「换个问法」，不给方向 | 给出**可点**的替代建议（取当前身份可见的文档标题与分类），点了直接重问 |
| 误点空查询 | 弹一句「先输入问题」 | 空输入时查询按钮直接禁用；有内容时出现清除按钮 |
| 键盘操作 | 只能鼠标点 | `/` 聚焦搜索框、`Enter` 提交、`Esc` 关弹窗 |
| 屏幕阅读器 | 结果变化不播报 | 结果区 `aria-live="polite"` + 查询期间 `aria-busy="true"` |
| 审计记录变多 | 只能从头翻 | 按结果 / 身份 / 操作类型筛选，并显示「筛选后 N 条 / 共 M 条」 |

**两个实现上的坑**（都已修，且有回归覆盖）：

1. **按钮复位时机**：`runGeneration` 是**不 await** 调用的（保持原有流式渲染结构），所以不能在 `answerQuery` 里统一 finally 复位按钮——否则生成还在跑、按钮就亮了。改为 `runGeneration` 自己 `try/finally` 复位，`answerQuery` 只在「拦截 / 拒答 / 证据」三条同步路径复位。
2. **复制按钮必须在文档查找之前返回**：结果区的点击委托是「反馈按钮 → 否则交给 `docAction`」，而 `docAction` 开头会 `state.docs.find(...)`，找不到就静默 `return`。所以 `copy-answer` / `reset-answer` 必须先于这次查找处理，否则点击无反应。

## 文档解析（DOCX / PDF）

导入 `DOCX` / `PDF` 时在浏览器内直接解析，**不引入任何第三方库、不上传文件**：

- **DOCX**：DOCX 本质是 ZIP。代码手写 ZIP 中央目录解析（EOCD → 中央目录 → 本地文件头），定位 `word/document.xml`，用 `DecompressionStream("deflate-raw")` 解压，再把 `w:p` / `w:t` / `w:pStyle` 转成段落与 Markdown 标题（`Heading1` / `标题 1` → `#`），标题层级因此能参与检索
- **PDF**：扫描 `stream…endstream` 取出内容流，`FlateDecode` 解压，解析 `ToUnicode` CMap（`beginbfchar` / `beginbfrange`）把字形码映射回 Unicode，再按 `Tj / TJ / Td / TD / T*` 文本操作符还原行序
- **扫描件会被识别并拒绝**：PDF 解析后做可读率校验（可读字符占比 < 0.5 或有效字符 < 20 即判定为图片型 / 加密 PDF），明确提示需先 OCR，**不回填正文**，避免把乱码写进知识库
- 单文件上限 8 MB；解析失败一律给出可读原因，不静默吞掉

实现细节与边界见 [`docs/文档解析说明.md`](docs/文档解析说明.md)。

## 服务端模式（可选）

纯本地模式有三条硬伤：身份靠下拉切换、可见范围只在前端过滤（改前端即可绕过）、审计存本机可被清空。`server/` 下的**零依赖 Node 参考实现**把权限与审计真正搬到服务端：

```bash
node server/server.mjs          # http://127.0.0.1:8787
```

然后在「资料与权限 → 服务端模式」填地址与账号（`employee` / `hr` / `manager` / `admin`，口令均 `demo1234`）连接。

| 能力 | 做法 |
| --- | --- |
| 真实身份 | 口令经 `scryptSync` 加盐哈希存储；登录签发 `base64url(payload).base64url(HMAC-SHA256)` token；服务端每次请求验签 + 校验过期 |
| 服务端权限 | `GET /api/documents` **先按身份过滤再序列化**——越权文档的任何字段都不出现在响应里；直接按 id 请求越权文档返回 **403**，且这次拒绝由服务端权威记入审计 |
| 写入侧 RBAC | 新增 / 启停 / 移除文档要求 `role === "admin"`，否则 403 并留痕 |
| 追加式审计 | `data/audit.jsonl` 只追加，不提供任何修改 / 删除接口；每条带 `prevHash` / `hash` 形成哈希链 |
| 篡改检测 | `verifyChain()` **每次读盘重算**，改写某条、删除插入、换序都会被检出并定位到行号 |
| 静态隔离 | 只托管 `index.html`；`/data/*` 与 `/server/*` 一律 404 |

**一个刻意的取舍**：检索没有下沉。授权在数据下发那一刻就完成了，检索只是对已授权数据做纯计算；把检索搬到服务端意味着复制一份算法（必然漂移）或把单文件应用拆成模块（破坏「双击即用」）。代价是服务端无法对「检索行为本身」限流审计——这一点连同其他上线前待办，都写在 [`docs/服务端说明.md`](docs/服务端说明.md) §9 与 §11。

> 哈希链只能**发现**篡改，不能**阻止**有文件写权限的人重算整条链；生产环境需要把日志推到独立只写存储，或对链尾做外部签名锚定。

## 离线评测

## 局限与边界（重要）

- **纯本地模式下的权限是演示级**：`ACCESS_POLICY` / `canAccess` / `authorize` 只在检索入口与渲染层做过滤，身份由顶部下拉手动切换，单机版无法实现真实的多用户身份认证与数据隔离。**接上 `server/` 参考实现后这一条才被真正解决**（出网前过滤 + 403 + 权威审计）。
- **纯本地模式下的审计可被本地清空**：审计记录存本机 IndexedDB，用户可自行清空（清空动作本身会留一条记录）。服务端模式下改为 append-only + 哈希链，但**哈希链只能发现篡改、不能阻止**有文件写权限的人重算整条链，生产环境仍需只写存储或链尾外部锚定。
- **服务端是参考实现，不是生产系统**：HTTP 明文、token 存 `sessionStorage`、不支持吊销、固定演示口令、文档存单机 JSON 文件。上线前待办逐条列在 [`docs/服务端说明.md`](docs/服务端说明.md) §11。
- **默认不联网**：不配置模型服务时，回答由原文分块拼接而成，表述不如生成式自然——好处是绝不会编造。配置模型服务后由模型组织语言，但**检索到的资料片段会随请求发送给该服务商**，涉密场景请改用内网网关或保持摘录模式。
- **生成层是产品约束，不是安全边界**：前置安全闸、引用校验、数值落地校验都在前端，改前端代码即可绕过。真实部署需要服务端网关统一持有密钥并做审计。
- **文件解析有边界**：TXT / MD / CSV / JSON / HTML 直接读取；DOCX 解析正文与标题层级（表格、图片、批注、页眉页脚不提取）；PDF 只支持**文本型** PDF（含 `ToUnicode` CMap 的中英文文档），**扫描件 / 图片型 PDF 会被识别并拒绝**，需先做 OCR；单文件上限 8 MB。
- **检索是词面匹配**：中文 2-gram + 拉丁 token + 14 组人工同义词表 + 标题权重，没有向量语义检索。同义词表已覆盖「口令↔密码」「薪水↔工资」这类真同义改写，但**上下位关系**（如「休假」vs「请假」）仍会漏召回；新领域需要补充词表。开启「检索重排」可缓解排序问题，但**不能解决召回不到**的问题。
- **重排依赖模型可用性**：重排只是锦上添花，接口不可用时自动回退原始排序；模型给出的顺序也未必比词面打分更准，建议在自有语料上对比后再决定是否开启。
- **数据只在本机**：清浏览器数据即丢失，请用「导出备份」留存。
- **语料为虚构演示内容**，不代表任何真实公司制度。

## 定位声明（避免误用）

这是一个**证据检索型问答的参考实现**，不是可以直接上线的企业系统。上线前还缺 TLS、企业身份（SSO / OIDC / MFA）、数据库与备份恢复、审计外送与留存、可观测性、CI/CD 等一整套东西，逐条差距与补齐优先级见 [`docs/企业级差距评估.md`](docs/企业级差距评估.md)。

尤其注意：**它的安全边界是产品约束，不是安全边界**——前置安全闸、引用校验、模型网关密钥都在前端，改前端代码即可绕过。
