# 架构说明

## 1. 设计目标与约束

| 目标 | 对应设计 |
| --- | --- |
| 回答必须有据可查 | 检索层只返回原文分块，不生成新内容；每条答案附来源文档与匹配度 |
| 资料不足不能编造 | 无命中或最高匹配度过低时走「暂未找到足够依据」分支；生成模式下**不调用模型** |
| 生成也要有据 | 可选生成层只把检索命中的分块作为上下文，强制标注来源，回答后校验引用与数值 |
| 兼顾信息权限 | 可见范围由显式策略表 `ACCESS_POLICY` 决定，检索与渲染入口统一经过 `canAccess()` / `authorize()` 判定 |
| 操作可追溯 | 关键操作（提问 / 拒答 / 拦截 / 查看 / 增删改 / 导出 / 切换身份）写入审计，可导出、可查看被拒次数 |
| 数据不出本机 | 全部数据存浏览器 IndexedDB；除可选的模型服务外无任何网络请求 |
| 零部署成本 | 单文件、无构建、无依赖、无后端 |

约束：**单文件**。所有 HTML / CSS / JS 内联在 `index.html` 里，便于直接分发和离线运行。

```
┌─────────────────────────────────────────────────────────┐
│ 视图层  page-ask / page-docs / page-audit / page-manage  │
│         顶部：演示身份切换 + 本机标识 + 当前回答模式       │
├─────────────────────────────────────────────────────────┤

│                   audit, answerZoomItems, llm, toastTimer}│
├─────────────────────────────────────────────────────────┤

│         → state.audit（内存）+ audit 仓库（持久化）       │
├─────────────────────────────────────────────────────────┤
│ 展示层  cleanMarkdown / renderMarkdownBody → 证据卡片     │
│         → 来源列表 → 放大阅读弹窗                         │
└─────────────────────────────────────────────────────────┘
```

## 3. 数据模型

### 知识文档 `documents`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | `doc-<uuid>` |
| `title` | string | 文档标题 |
| `category` | string | 分类：人事制度 / 财务报销 / 办公流程 / 其他 |
| `audience` | `all` \| `hr` \| `manager` | 可见范围，取值即 `ACCESS_POLICY` 中策略表的 `audiences` 元素 |
| `status` | `active` \| `inactive` | 停用后不参与检索，但仍保留在知识库 |
| `source` | string | 来源文件名或「手动录入」 |
| `body` | string | 正文（Markdown 或纯文本），上限 200,000 字符 |
| `createdAt` / `updatedAt` | ISO string | 时间戳 |

### 反馈 `feedback`

`{ query, value: "yes" | "no", role, createdAt }`，用于记录「这条资料有帮助吗」。

### 审计 `audit`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 自增主键（IndexedDB autoIncrement） |
| `at` | ISO string | 发生时间 |
| `role` | `employee` \| `hr` \| `manager` \| `admin` | 操作时的演示身份 |
| `action` | string | 动作码，见 `AUDIT_LABELS` 映射（如 `query` / `open_document` / `audit_clear`） |
| `target` | string | 操作对象（文档标题等），可为空 |
| `detail` | string | 补充说明（问题原文、命中条数、拒绝原因等） |
| `result` | `allowed` \| `denied` | 是否被权限拒绝 |

内存里 `state.audit` 保持最近 `AUDIT_LIMIT = 300` 条（新的在前），与仓库写入相互独立——渲染读内存、持久化走仓库，避免每次操作都重查全表。

### 模型服务配置 `localStorage: zhigui-llm-config`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `enabled` | boolean | 是否启用生成式回答 |
| `baseUrl` | string | OpenAI 兼容接口的 Base URL（不含 `/chat/completions`；拉取模型时拼 `/models`） |
| `model` | string | 模型名称 |
| `apiKey` | string | 仅存本机；**不写进导出备份** |
| `temperature` | number | 默认 0.2 |
| `rerank` | boolean | 是否启用检索重排，默认 `false` |

判定生成模式就绪：`enabled && baseUrl && model`（`llmReady()`）。

## 4. 关键流程

### 4.1 启动

```
openDB() → loadDocs()（按 updatedAt 倒序）
         → seedIfEmpty()（首次运行时写入 5 份演示制度）
         → loadAudit()（读审计仓库，回填 state.audit）
         → renderAll()（统计 / 文档网格 / 审计列表 / 访问范围表）
```

### 4.2 提问（`answerQuery`）

```
读取 #questionInput
  ├─ 空 → toast 提示
  └─ 非空
       ├─ preflightGate(query)：长度 / 提示注入 / 批量导出 → 拦截
       │    └─ recordAudit("query_blocked", { result: "denied" })
       ├─ requestedOrdinal(query)：识别「追问2 / 第3题 / 序号5」等显式序号
       ├─ retrieve(query) → 证据列表
       ├─ 无结果，或（无显式序号且最高覆盖度 < 0.24）→ 拒答分支
       │    └─ recordAudit("query", { detail: "…（无匹配依据，已拒答）" })
       └─ 有结果
            ├─ llmReady() ? runGeneration() : renderEvidenceAnswer()
            ├─ recordAudit("query", { detail: "…（生成式/证据摘录，N 条证据）" })
            ├─ 写入 state.answerZoomItems（供放大弹窗读取）
            └─ 渲染：答案单元 / 生成回答 + 来源列表 + 反馈按钮
```

- `renderEvidenceAnswer()` —— 原文证据摘录（默认路径）
- `runGeneration()` —— 生成式回答（可选路径，见 4.6）

### 4.3 权限校验（`ACCESS_POLICY`）

可见范围不再散落在各处 `if`，而是收敛成一张显式策略表：

```js
const ACCESS_POLICY = {
  employee: { label: "员工",   audiences: ["all"] },
  hr:       { label: "人事",   audiences: ["all", "hr"] },
  manager:  { label: "主管",   audiences: ["all", "manager"] },
  admin:    { label: "管理员", audiences: ["all", "hr", "manager"] }
};
function canAccess(role, doc) {
  const policy = ACCESS_POLICY[role];
  return !!policy && policy.audiences.includes(doc.audience);
}
function authorize(doc, action = "查看") {
  if (canAccess(state.role, doc)) return { allowed: true, reason: "" };
  return { allowed: false, reason: `当前演示身份「${roleNames[state.role]}」没有${action}该文档的权限…` };
}
function visible(doc) { return canAccess(state.role, doc); }
```

调用点：检索入口（`retrieve` 遍历文档前）、文档网格渲染（无权卡片加 `.restricted` 样式并标注）、来源打开（`openDocument` 用 `authorize()` 决定是否放行）、访问范围表渲染（`renderPermissionTable()` 直接由策略表生成，与实现同源）。

> ⚠️ 这是**演示级**校验。单机应用无法阻止用户改前端代码或直接读 IndexedDB。真实部署必须把同一套策略放到服务端，无权时返回 403。

### 4.4 文档导入

```
选择文件 → extractTextFromFile()
  ├─ 扩展名白名单：txt / md / markdown / csv / json / html / htm / docx / pdf
  ├─ 大小校验（文本 ≤ 1 MB；DOCX / PDF ≤ 8 MB）
  ├─ HTML   → DOMParser，剥离 script / style / noscript
  ├─ DOCX   → readZipDirectory() → word/document.xml → inflate("deflate-raw")
  │            → docxXmlToMarkdown()（w:p 分段、w:pStyle → Markdown 标题）
  ├─ PDF    → 扫描 stream → FlateDecode → ToUnicode CMap → Td/TD/T* 分行
  │            → readableRatio 校验，可读率不足即拒绝（扫描件 / 加密件）
  └─ 其余按 UTF-8 文本读入
→ 回填标题与正文 → saveDocument() → transaction put → loadDocs() → 重渲染
```

解析细节见 [`文档解析说明.md`](文档解析说明.md)。

### 4.5 操作审计（`recordAudit`）

```js
function recordAudit(action, options = {}) {
  const entry = { at: new Date().toISOString(), role: state.role, action,
                  target: options.target || "", detail: options.detail || "",
                  result: options.result || "allowed" };
  state.audit = [entry, ...state.audit].slice(0, AUDIT_LIMIT);  // 内存，新的在前
  renderAudit();                                                // 立即刷新审计页
  transaction("audit", "readwrite", store => store.add(entry)).catch(() => {});  // 持久化
  return entry;
}
```

审计与业务动作**同一处触发**，避免「业务改了、审计没跟上」。当前记录点：

| 动作码 | 触发时机 | 结果 |
| --- | --- | --- |
| `query` | 正常提问有依据 / 无依据拒答 | allowed |
| `query_blocked` | 前置安全闸拦截（注入、批量导出） | denied |
| `open_document` | 打开文档；越权时 | allowed / **denied** |
| `import_document` / `edit_document` / `toggle_document` / `delete_document` | 文档增删改启停 | allowed |
| `export_backup` | 导出 JSON 备份 | allowed |
| `llm_config` | 保存 / 清除模型配置 | allowed |
| `llm_models` | 拉取可用模型列表（成功 / 失败） | allowed / **denied** |
| `role_switch` | 切换演示身份 | allowed |
| `audit_export` / `audit_clear` | 导出 / 清空审计（清空动作本身也留痕） | allowed |

审计页顶部汇总「记录总数 / 被拒绝操作数 / 当前身份」，列表按时间倒序；`denied` 行标红。导出走 Blob 下载，文件名含时间戳。

> 以上是**纯本地模式**的记录点。接上 `server/` 参考实现后，前端只上报**白名单内**的纯前端事件（`query` / `query_blocked` / `copy_text` / `llm_config` / `llm_models` / `role_switch`），落盘标记 `source=client`，与 `source=server` 的权威记录在**存储层**可区分；`open_document`、文档增删改这类与授权相关的动作由服务端自行记录，不走客户端上报。详见 [`服务端说明.md`](服务端说明.md) §7。

### 4.6 生成式回答（`runGeneration`，可选）

```
检索已有结果 + 通过前置安全闸
  ├─ 渲染骨架「正在依据 N 条资料生成回答…」
  ├─ buildContext(results)：取前 3 条，编号 [1][2][3]，带文档标题 + 编号小节全文
  ├─ requestGeneration()：POST {baseUrl}/chat/completions（stream: true，SSE 增量）
  │    └─ 非 text/event-stream 响应自动按 JSON 解析
  ├─ 成功
  │    ├─ 边收边用 renderMarkdownBody 渲染
  │    ├─ verifyGenerated()：引用越界 / 无引用 → 警告
  │    ├─ ungroundedNumbers()：来源中找不到的金额比例天数 → 警告
  │    └─ 渲染来源列表（与 [n] 编号一一对应）
  └─ 失败（网络 / HTTP / 空响应）
       └─ renderEvidenceAnswer(..., errorNote) 同屏回退为证据摘录
```

生成式结果的三条核对路径：① 回答卡片整体挂 `.answer-zoom-trigger`，放大弹窗上半部分是生成回答、下半部分是**逐字来源原文**（`zoomItemForGeneration`）；② 标签行的「查看原文证据」按钮（`data-action="show-source"`）一键切回逐字原文模式，依赖 `state.lastResults` 保存的 `{ query, results, target }`；③ 系统提示词要求专有名词与关键数值照抄原文措辞。

关键约束：**拒答分支在生成之前**——没有检索依据时根本不会发起模型请求。协议与安全闸细节见 [`生成层说明.md`](生成层说明.md)。

### 4.7 可用模型列表（`fetchModelList`）

```
点击「拉取模型列表」
  ├─ Base URL 为空 → toast 提示并聚焦输入框（不发请求）
  ├─ GET {baseUrl}/models（带 Authorization: Bearer <apiKey>，无 Key 则不带）
  ├─ 非 2xx → 提示条「拉取失败：HTTP 401（…）」+ 列表收起 + 审计 denied
  ├─ normalizeModelList(payload)：data[] / models[] / result[] / 数组 / 字符串
  │    → { id, ownedBy, created, extra }（上下文长度 / 最大输出 / 参数规模 / 体积 / 量化格式）
  ├─ 0 条可识别 → 提示手动填写 + 列表收起 + 审计 denied
  └─ 成功 → renderModelList() 渲染可点选列表 + 审计 allowed
                └─ 点击某项 → pickModel(id) → 填入 #llmModel 并标记 picked
```

该动作**不修改任何配置**，也不影响当前回答模式。

### 4.8 检索重排（`rerankWithLLM`，可选）

在 `answerQuery` 中，检索完成、判定为「有依据」之后、进入渲染之前：

```
results = retrieve(query)
if (results.length > 1 && state.llm.rerank && llmReady())
     → POST {baseUrl}/chat/completions（temperature 0，stream false）
     → 解析返回的数字顺序 → 过滤越界 → 去重 → 重排 → 未提及的补到末尾
     → 任一环节失败 / 返回不可解析 → 返回原序（无用户可见报错）
```

重排只改**顺序**，不改集合，因此来源编号 `[1][2][3]` 与 `verifyGenerated` 的引用校验、`ungroundedNumbers` 的数值校验都不受影响。

### 4.9 答案放大阅读

答案卡片是 `<button class="answer-zoom-trigger" data-answer-index="i">`。点击后由 `docAction` 分派到 `openAnswerZoom(i)`，从 `state.answerZoomItems[i]` 取内容写入 `#answerZoomBody`（字号 `clamp(17px, 2.1vw, 23px)`，可滚动）。关闭方式：关闭按钮 / 完成按钮 / 点击遮罩 / `Esc`。

条目有两种载荷：带 `html` 的（生成式回答，含生成内容 + 逐字原文对照）走 `innerHTML` 并加 `.zoom-html` 类；不带 `html` 的（证据摘录）走 `textContent` 并保留 `white-space:pre-wrap`。

**注意**：两种回答模式都必须挂 `.answer-zoom-trigger`。生成式模式早期漏挂，导致「生成式回答点不开」。

## 6. 已知边界

1. **单机、单用户**：没有账号体系，`role` 只是演示开关；策略表在前端，改代码即可绕过。**服务端模式下由 `server/` 参考实现补齐**（真实登录 + 出网前过滤 + 403 + 追加式审计），见 [`服务端说明.md`](服务端说明.md)。
2. **无服务端时**：没有并发、真实多用户隔离、加密、备份恢复能力；审计存本机、可被本地清空，不防篡改。服务端模式解决了权限与审计两块，其余（并发、加密、备份恢复）仍在待办。
3. **默认无 LLM**：不配置模型服务时，回答是原文摘录拼接。配置后由模型组织语言，但检索片段会发给该服务商。
4. **生成层是产品约束而非安全边界**：前置安全闸、引用校验、数值校验都在前端，改代码即可绕过；真实部署需服务端网关。
5. **解析范围有限**：DOCX 只取正文与标题层级（表格线性输出、图片/批注/页眉页脚忽略）；PDF 只支持文本型（含 ToUnicode CMap），扫描件与加密件会被拒绝。
6. **检索为词面匹配**：无向量语义召回，同义改写可能漏召回；标题权重与 LLM 重排只能改善**排序**，改善不了**召回**。
7. **重排多一次网络往返**：默认关闭；开启后每次多结果查询都会额外调用一次模型。
