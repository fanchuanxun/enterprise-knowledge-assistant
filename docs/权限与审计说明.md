# 权限与审计说明

## 1. 设计目标

| 目标 | 落地方式 |
| --- | --- |
| 权限规则可读、可核对 | 用一张显式策略表 `ACCESS_POLICY` 作为唯一事实来源，界面上的权限表也由它渲染 |
| 规则与实现不分叉 | 检索过滤、文档打开、权限表渲染共用同一个判定函数 `canAccess()` |
| 越权必须被拒绝并留痕 | 拒绝时给用户明确提示，同时写入审计（`result: "denied"`） |
| 操作可追溯 | 问答、查看、维护、导出、配置变更全部记入 IndexedDB 的 `audit` 仓库，可导出 JSON |

## 2. 访问策略表

```js
const ACCESS_POLICY = {
  employee: { label: "员工",   audiences: ["all"] },
  hr:       { label: "人事",   audiences: ["all", "hr"] },
  manager:  { label: "主管",   audiences: ["all", "manager"] },
  admin:    { label: "管理员", audiences: ["all", "hr", "manager"] }
};
function canAccess(role, doc) {
  const policy = ACCESS_POLICY[role];
  return !!policy && policy.audiences.includes(doc.audience);
}
```

文档侧只有三个可见范围值：`all` / `hr` / `manager`（对应「所有员工 / 仅人事 / 仅主管」）。

**共用点**（改一处即全局生效）：

| 位置 | 用法 |
| --- | --- |
| 检索入口 `retrieve()` | `if (doc.status !== "active" || !visible(doc)) continue;` |
| 文档打开 `openDocument()` | `authorize(doc, "查看")`，不通过则拒绝 |
| 文档列表 `renderDocs()` | 无权查看的卡片加 `.restricted` 样式并标注「当前身份无权查看」 |
| 权限面板 `renderPermissionTable()` | 表格直接从 `ACCESS_POLICY` 生成，不会与实现脱节 |
| 统计 `renderStats()` | 只统计当前身份可见的启用文档 |

`authorize()` 返回结构化结果，便于区分「界面提示」与「审计原因」：

```js
function authorize(doc, action = "查看") {
  if (canAccess(state.role, doc)) return { allowed: true, reason: "" };
  return { allowed: false, reason: `当前演示身份「${roleNames[state.role]}」没有${action}该文档的权限（该文档可见范围：${audienceNames[doc.audience]}）。真实部署中应由服务端返回 403。` };
}
```

## 3. 审计数据模型

IndexedDB `zhigui-local-knowledge` 的 `audit` 仓库（keyPath `id`，autoIncrement，DB 版本 2 新增）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 自增主键 |
| `at` | ISO string | 发生时间 |
| `role` | string | 操作时的演示身份 |
| `action` | string | 动作类型（见下表） |
| `target` | string | 操作对象（如文档标题、模型名） |
| `detail` | string | 补充说明（问题原文、可见范围、条数等） |
| `result` | `allowed` \| `denied` | 结果 |

内存侧 `state.audit` 保留最近 300 条用于渲染，列表展示最近 40 条。

### 记录点

| `action` | 界面标签 | 触发时机 | 备注 |
| --- | --- | --- | --- |
| `query` | 知识问答 | 每次提问 | 含模式与证据条数；无依据时标注「已拒答」 |
| `query_blocked` | 问答被拦截 | 前置安全闸命中 | `result: denied` |
| `open_document` | 查看文档 | 打开文档 | 越权时 `result: denied` |
| `import_document` | 导入文档 | 新建文档保存成功 | |
| `edit_document` | 编辑文档 | 修改已有文档保存 | |
| `toggle_document` | 启停文档 | 启用 / 停用 | |
| `delete_document` | 移除文档 | 确认移除后 | |
| `export_backup` | 导出备份 | 导出知识库 JSON | |
| `llm_config` | 模型配置 | 保存 / 清除模型服务配置 | 不记录密钥本身 |
| `role_switch` | 切换身份 | 顶部身份下拉变更 | |
| `audit_export` | 导出审计 | 导出审计日志 | |
| `audit_clear` | 清空审计 | 清空日志 | 清空后会记录这一条本身 |
| `client_event_rejected` | —（服务端模式） | 客户端上报了白名单外的事件 | `result: denied`；服务端权威留痕，`source: server` |
| `audit_read` | —（服务端模式） | 非管理员尝试读取服务端审计 | `result: denied`；服务端权威留痕 |

> 服务端模式下，`audit.jsonl` 的条目在上述字段之外还有 `seq` / `prevHash` / `hash` / `user` / `ip` / `source`：`user` 与 `ip` 由服务端补全（前端伪造不了），`source` 区分 `server`（服务端权威记录）与 `client`（前端上报的声明）。详见 [`服务端说明.md`](服务端说明.md) §7。

## 4. 界面

新增左侧导航「操作审计」（`#page-audit`）：

- **汇总**：记录总数 / 被拒绝操作数 / 当前演示身份
- **列表**：时间 · 身份 · 操作 · 对象详情 · 结果；`denied` 行以浅红底色与红色「已拒绝」标识
- **导出审计日志**：下载 `zhigui-audit-YYYY-MM-DD.json`，格式 `zhigui-audit-log-v1`
- **清空日志**：二次确认后清空，并记录清空动作

文档列表同时增强：当前身份无权查看的文档以虚线卡片展示，并标注「当前身份无权查看」；点击「查看」会被拒绝并留下一条 `denied` 审计——越权路径因此可演示、可测试。

## 6. 边界（务必明确）

- **不是真实权限控制**：`role` 来自前端下拉框，任何人改一下 `localStorage` / 直接操作 IndexedDB 即可绕过。真实部署必须由服务端完成身份认证与逐请求鉴权。
- **审计可被本地清空或篡改**：单机版本无法防抵赖。真实部署需要把审计写入服务端不可篡改存储（追加写 + 独立留存），并与账号体系绑定。
- **审计不含数据内容**：只记录问题原文、文档标题与可见范围，不记录文档正文，避免日志本身成为泄露面。
- **记录上限**：内存渲染保留最近 300 条；IndexedDB 内不设上限，如需长期留存请定期导出。

## 7. 服务端模式下这些边界怎么变

本节描述的机制是**纯本地模式**下的行为，也是「资料与权限」页那张访问范围表的适用前提。接上 `server/` 参考实现后：

| 维度 | 纯本地模式 | 服务端模式 |
| --- | --- | --- |
| 身份来源 | 前端下拉框 | 登录后由服务端签发 HMAC token，前端不可伪造 |
| 可见范围判定点 | 检索入口 + 卡片渲染（同一份 `ACCESS_POLICY`） | 服务端 `GET /api/documents` **出网前过滤**，越权文档不下发；按 id 请求越权文档 403 |
| 写操作 | 前端直接写 IndexedDB | 服务端校验 `role === "admin"`，否则 403 |
| 审计存储 | IndexedDB，前端可清空 | `data/audit.jsonl` 追加写，无修改 / 删除接口 |
| 篡改检测 | 无 | 哈希链 `verifyChain()` 读盘重算，可定位到行 |
| 客户端上报的可信度 | 前端写什么就是什么 | `/api/events` 动作白名单 + 落盘标记 `source=client` + 同用户 1 分钟限 60 条；被拒请求权威留痕 |
| 前端改代码能绕过吗 | 能 | 拿不到未授权数据（但检索仍在前端，见 §9 of 服务端说明） |

前端 `index.html` 里的 `ACCESS_POLICY` 在服务端模式下退化为**渲染与提示**用途，判定权在服务端。完整设计、接口与上线前待办见 [`服务端说明.md`](服务端说明.md)。
