# 企业级差距评估

> 一句话结论：**这是一个把「企业级问题」都碰到、并给出了正确解法的参考实现，不是企业级生产系统。**
> 它可以作为立项可行性验证、面试作品、教学参考；**不能直接上线承接真实企业数据。**

本文只写事实与可复现的差距，不做修饰。所有代码引用均可在仓库中核对。

## 二、已经做对的（有测试证据）

这些不是「写了就算」，都有对应断言：

1. **权限判定是单一事实来源**：`server/policy.mjs` 与前端 `ACCESS_POLICY` 语义一致；越权在**序列化之前**过滤（`visibleDocuments`），越权文档的任何字段都不出现在响应里。
2. **审计哈希链真的能发现篡改**：`AuditLog.verifyChain()`（`server/audit.mjs:77`）**每次从磁盘重读**再逐条重算。测试里直接改写 `audit.jsonl`，被检出并**定位到第 2 行**；还原后恢复完整。
3. **越权拒绝由服务端权威记录**（`server/server.mjs:197`），不依赖客户端上报。
4. **口令存储**：`scryptSync` 加盐哈希 + `timingSafeEqual` 比较；**用户不存在时也做一次等价开销的哈希**（`server/auth.mjs:89-93`），避免通过响应时间枚举用户名。
5. **没有引入 JWT**：自签 `base64url(payload).base64url(HMAC-SHA256)`，因而绕开了 `alg=none` 这类经典坑。
6. **生成层「无依据不调用模型」**：检索不到证据时直接拒答，`llm-layer-test` 会核对 mock 端的**请求计数**，确认一次请求都没发出去。
7. **拒答优先于编造**：语料中不存在该主题时必须明确拒答，26 条拒答用例全过。
8. **零依赖**：只用 `node:` 内置模块，双击 `index.html` 即可运行。
9. **静态隔离**：只托管 `index.html`，`/data/*` 与 `/server/*` 一律 404，连「路径存在」的信号都不给。
10. **审计可信度分层**：`/api/events` 只接受 6 类纯前端事件（动作白名单），落盘标记 `source=client`，与 `source=server` 的权威记录在**存储层**就可区分；`source` 参与哈希链计算；`/api/audit` 返回 `{ server, client }` 计数。被拒上报本身也由服务端权威留痕（`client_event_rejected` / `denied`）。

## 三、差距清单（按企业级维度）

| 维度 | 企业级要求 | 当前实现 | 差距 |
| --- | --- | --- | --- |
| 身份 | 对接 SSO / OIDC / LDAP，MFA，口令策略 | 本地 `users.json` + 4 个演示账号 | 无 SSO、无 MFA、无口令复杂度与轮换 |
| 传输 | TLS + 证书管理 + HSTS | **纯 HTTP 明文** | 口令与 token 明文过网 |
| 会话 | 可吊销、可刷新、单点登出 | HMAC token，无 `jti`、无会话表 | **签发后无法吊销**；角色变更最长 120 分钟才生效 |
| 存储 | 数据库 + 事务 + 备份恢复 + 静态加密 | 单机 JSON 文件，全量重写 | 非原子写、无并发控制、无备份、无静态加密 |
| 审计 | 只写存储 / SIEM，留存期限，不可否认 | 本机 JSONL + 哈希链 | 哈希链**只能发现不能阻止**重算整条链；无留存策略、无异地推送 |
| 授权 | 统一策略中心 + 细粒度（字段级 / 数据级） | 硬编码 3 档 audience（all / hr / manager） | 无角色管理界面、无字段级权限 |
| 可观测 | 日志 / 指标 / 告警 / 链路追踪 | `console.log` | 全无 |
| 高可用 | 多实例无状态 + 共享存储 | 单进程 + `documents` 常驻内存 | 无法水平扩展；重启依赖文件重载 |
| 性能 | 压测基线 + 容量规划 | 无任何性能测试 | 容量未知 |
| 安全 | CSP / 安全响应头 / 依赖扫描 / 渗透测试 | 无安全响应头，CORS 默认 `*` | 见下方逐条 |
| 交付 | CI/CD、容器化、配置管理、灰度回滚 | 无 CI、无 lint、无 Dockerfile | 全无 |
| 合规 | 等保、数据分级、脱敏、留存 | 无 | 全无 |
| 测试 | 单元 + 集成 + E2E + 性能 + 安全 | E2E + 判定逻辑单测 | 无性能 / 安全测试；业务模块（检索 / 权限 / 审计）无模块级单测 |

## 四、代码级发现（逐条可核对）

| # | 位置 | 问题 | 影响 |
| --- | --- | --- | --- |
| 1 | `server/server.mjs:41` | `ZHIGUI_CORS_ORIGIN` 默认 `*`，且允许 `Authorization` 头 | 演示方便；生产必须收紧为白名单 |
| 2 | `server/server.mjs:59` | `clientIp` 只取 socket 地址，**不读 `X-Forwarded-For`** | 部署在反向代理后，登录限速会把所有请求算作同一 IP（形同失效），审计里的 IP 也是错的 |
| 3 | `server/server.mjs:102-114` | 登录失败计数在内存 `Map`，重启清零；过期项从不清理 | 重启即可绕过限速；长期运行内存缓慢增长 |
| 4 | `server/server.mjs:318-357` | ~~`/api/events` 接受任意已登录用户提交的任意 `action` / `detail`~~ **已修复** | 现加动作白名单（6 类纯前端事件）+ 落盘标记 `source=client`；非白名单事件 400 且权威留痕，取证时可区分权威记录与客户端声明 |
| 5 | `server/server.mjs:56` | `saveDocuments()` 用 `writeFileSync` 全量重写 | **非原子**：写到一半崩溃会损坏 `documents.json`；并发管理员写入会互相覆盖 |
| 6 | `server/server.mjs:300` | `/api/audit` 每次调用都执行 `verifyChain()`（读整个文件） | O(n)，随日志增长线性变慢 |
| 7 | `server/server.mjs:61-72` | 无 `Content-Security-Policy` / `X-Content-Type-Options` / `X-Frame-Options` / HSTS | 缺纵深防御 |
| 8 | `server/auth.mjs:46` | token payload 无 `jti` | 无法按会话追踪或吊销单个 token |
| 9 | ~~除登录外无任何限速~~ **已部分修复** | 登录失败限速（5 分钟 10 次）；`/api/events` 已加同用户 1 分钟 60 条限速 | 审计文件仍**无轮转**，长期运行仍会无限增长；无全局请求体上限 |
| 10 | 前端 token 存 `sessionStorage` | 任何 XSS 可直接取走；且无 CSP 兜底 | 单点失守即全失守 |
| 11 | `server/server.mjs:126` | 每次请求 `readFileSync(index.html)` | 无缓存，大文件下低效（演示规模无感） |
| 12 | 检索在浏览器本地执行 | 服务端无法对「检索行为本身」限流与审计 | 这是**刻意的取舍**（见 `docs/服务端说明.md` §9），不是遗漏 |

## 五、如果真要上企业，最少还要做什么（按优先级）

**P0 — 不做就不能上生产**

1. **TLS 终结**：HTTPS + HSTS，证书自动轮换。
2. **接入企业身份**：对接 SSO / OIDC / LDAP，去掉本地演示口令；至少补 MFA 与口令策略。
3. **存储换成数据库**：事务、并发控制、定期备份 + **恢复演练**（没演练过的备份等于没有备份）。
4. **审计外送**：日志实时推送到独立只写存储（对象存储 WORM / 日志服务 / SIEM），或对链尾做外部签名锚定；明确留存期限。
5. **收紧 CORS 与安全响应头**；补 CSP。
6. **修 `clientIp`**：信任链上正确解析 `X-Forwarded-For` / `X-Real-IP`。

**P1 — 上生产后必须尽快补**

7. **会话可吊销**：服务端会话表或短时效 access + refresh token；补单点登出。
8. **限速与配额**：~~`/api/events` 限速~~ **已加（同用户 1 分钟 60 条）**；仍需全局限速 + 请求体上限 + **审计文件轮转**。
9. **可观测性**：结构化日志、关键指标（登录失败率、403 率、模型调用失败率）、告警。
10. **CI/CD**：跑通十套测试再允许合并；镜像化与配置外置；灰度与回滚预案。
11. ~~**审计可信度分层**~~ **已完成**：`source=server` / `source=client` 在存储层分离且参与哈希链，`/api/audit` 返回来源计数。

**P2 — 规模与质量**

12. **性能基线**：压测得到 QPS / 延迟 / 并发上限，据此做容量规划。
13. **单元测试与安全测试**：补模块级单测、依赖漏洞扫描、渗透测试。
14. **多实例化**：去掉进程内状态，文档与审计改为共享存储，支持水平扩展。
15. **合规对齐**：等保要求、数据分级与脱敏、访问留痕留存期限。

## 六、这个作品当前适合用来做什么

**适合**

- **面试 / 作品集演示**：能完整讲清「权限怎么落到数据下发那一刻」「审计怎么做到可发现篡改」「生成式回答怎么不编造」，且每一条都有测试与文档支撑。
- **内部立项的可行性验证**：把「证据检索型问答」这条链路跑通，用 118 条评测说明检索质量，用拒答率说明「不编造」不是口号。
- **教学参考**：单文件前端 + 零依赖服务端，权限、审计、解析、检索四个模块都可以单独拆出来讲。

**不适合**

- 直接上线承接真实企业数据。
- 当作「企业级安全产品」宣传——它的安全边界是**产品约束**，不是安全边界（前端代码可改，模型网关密钥在前端）。

**一句话**：骨架是对的，零件是合格的，缺的是把它装进生产环境的那一整套（TLS、SSO、数据库、外送审计、CI/CD、可观测）。这些不是「再改几行代码」，而是另一量级的工程量。
