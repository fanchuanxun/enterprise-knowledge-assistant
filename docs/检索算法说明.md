# 检索算法说明

> 目标：在**不引入向量库和外部模型**的前提下，让中文制度文档的问答尽可能准，且宁可拒答也不编造。

## 1. 整体流程

```
query
 ├─ ⓪ 同义词归一化        applySynonyms()  → 变体统一为规范词
 ├─ ① 识别显式序号        requestedOrdinal()
 ├─ ② 分块                buildSections()  → 带 headingNumber 的分块列表
 ├─ ③ 逐块打分            scorePassage()   → coverage / exact / score
 ├─ ④ 阈值过滤            minimumCoverage（或问答块 0.75）
 ├─ ⑤ 主题一致性校验      命中词不能全是通用词（审批 / 流程 / 申请…）
 ├─ ⑥ 编号小节聚合        按 headingNumber 合并成「一条完整答案」
 ├─ ⑦ 相对过滤 + 排序去重  score ↓ / coverage ↓ / 长度 ↓
 └─ ⑧ 取前 N 条 + 拒答判定
```

## 2. 分词（`termsOf`）

中文没有空格，这里用 **2-gram** 近似切词：

1. `applySynonyms`：先把同义词变体替换为规范词（见 §2.1）
2. `normalize`：转小写，去掉空白、标点与符号（Unicode `\p{P}\p{S}`）
3. 抽出所有 CJK 连续段，**先删疑问短语、再删单字虚词**，最后切成相邻双字
4. 抽出拉丁 / 数字 token：长度 ≥ 2，或**单个大写字母**（用于 `Q` / `K` / `V` 这类缩写）
5. 丢弃「两个字符都是功能字」的 2-gram（如 `可以` `需要`）
6. 去重

**疑问短语**（整体删除——若不整体删，「什么时候」会被切成「时候」留下噪声 2-gram）：

```
什么时候 多长时间 多久 多少 哪些 哪个 哪里 几点 几号 几天 几次
为什么 怎么办 怎么样 怎样 怎么 如何 什么 请问 一下 关于
能否 是否 之后 之前 以后 以前 以及 并且 但是 因为 所以 时候
```

**单字虚词**（只保留不会破坏实义词的字）：`与 和 及 或 的 是 了 吗 呢 我 你 他 她 它 把 被 从`

**功能字**（用于丢弃纯噪声 2-gram）：`的 了 是 在 对 把 被 从 到 我 你 他 她 它 吗 呢 与 和 及 或 有 为 就 都 也 还 需 可 以 能 会`

> ⚠️ **踩过的坑**：早期版本把 `到` `还` `对` `为` `有` 也当虚词删掉，结果把 `归还` 切成 `归`、`到场` 切成 `场`，直接导致「辞职后设备要归还吗」拒答。删虚字前必须确认它不会出现在实义词里——这个回归同样是评测抓出来的。

> 更早的版本还同时生成 3-gram，实测导致 `coverage` 分母过大、召回明显下降（「年假」问不到休假制度），已移除。

**例**：`年假要提前几天申请` → `年假 假要 要提 提前 前申 申请`（`几天` 被整体删除）

### 2.1 同义词归一化（`applySynonyms`）

词面匹配对「同义不同词」无能为力（`口令` vs `密码`、`薪水` vs `工资`）。这里维护一张**归一表**：组内第一个是规范词，其余变体在打分前统一替换成规范词，于是 query 用 `口令`、原文用 `密码` 时也能命中。

| 规范词 | 变体 |
| --- | --- |
| 工资 | 薪资 薪水 薪酬 月薪 |
| 社保 | 社会保险 五险一金 |
| 密码 | 口令 |
| 调休 | 补休 |
| 报销 | 报账 |
| 差旅 | 出差 |
| 离职 | 辞职 离岗 |
| 审批 | 审核 签批 核准 |
| 材料 | 资料 单据 凭证 票据 |
| 预约 | 预订 |
| 入职 | 报到 |
| 年假 | 年休假 |
| 病假 | 病休 |
| 电脑 | 计算机 |

归一化**只作用于打分**（query 与分块文本同时归一），不改动展示给用户的原文。

> 只收录**真同义**词，不放上下位关系（如 `年假` 与 `请假`），否则会把「年假可以折现吗」这类无依据问题误召回成有答案。

## 3. 打分（`scorePassage`）

```js
matches  = terms.filter(t => passage.includes(t))
coverage = matches.length / terms.length      // 命中词占比，主信号
exact    = 归一化后整句出现在分块中            // 整句命中
score    = coverage * 5 + (exact ? 3 : 0) + min(matches.length, 8) * 0.16
```

`coverage` 决定「像不像」，`score` 用于排序，`exact` 用来在长问题下兜底。

### 3.1 标题权重

正文覆盖率有个天然盲区：**答案的落点常常写在标题里**。例如问「发薪日是什么时候」，资料 `2.1 发薪日` 的正文只写「每月 15 日发放上月工资」，「发薪日」三个字只在标题中。

因此对每个候选分块**额外对标题打一次分**：

```js
titleMatch  = scorePassage(query, section.headingTitle)   // 标题单独打分
titleCoverage = titleMatch.coverage                        // 标题覆盖度（独立保留，用于展示与二级排序）
score = match.score + titleMatch.score * 0.5 + min(labelMatch.score * 0.08, 0.25)
```

- **权重 0.5** 而不是 1.0：标题很短，命中一个词就能拿到很高的覆盖度，权重过高会让「标题里恰好有个同名词」的分块压过正文真正命中的分块
- 打分文本仍是 `标题 + 正文` 拼接（保证标题里的词能被正文匹配路径命中），标题权只是**额外加成**
- `titleCoverage` 单独保留下来，既参与排序（第二排序键），也展示在来源列表里（`· 标题匹配 NN%`），便于人工判断「这条是靠标题命中的」
- 标签（`【追问N】` 这类 `label`）另给 0.08 的弱权重并封顶 0.25——它只是辅助定位，不应主导排序

> **注意**：标题权重只作用于常规检索分支。显式序号查询（`追问2`）走的是独立分支，不参与本权重，以免改变「按序号精确取答案」的语义。

## 4. 分块（`buildSections`）

两种模式：

**A. 有 Markdown 标题**

按 `#`~`######` 切分。每个分块记录四个元数据：

| 字段 | 含义 |
| --- | --- |
| `headingNumber` | **最近的带编号祖先**小节号（正则 `/^\s*(\d+(?:\.\d+)+)\b/`，如 `1.1`） |
| `headingTitle` | 该祖先标题全文（如 `1.1 工作时间`） |
| `headingLevel` | 该祖先的标题层级 |
| `headingContext` | 若当前分块自身不是编号标题，记录自己的标题名（用于展示层级） |

标题下的内容再按段落切分；识别 `【追问N】/ 问题N / 题目N / Q N` 分组标记，作为 `label` 挂在分块上。

**B. 无 Markdown 标题**

按空行分段；短行（< 72 字符且不以句末标点结尾）视为下一段的标签；超长段落（> 560 字符）按句子切到约 480 字符一块。

## 5. 阈值（`minimumCoverage`）

| 查询词数 | 阈值 | 理由 |
| --- | --- | --- |
| ≥ 4 | 0.35 | 长问题词多，覆盖率天然被摊薄 |
| 2 ~ 3 | 0.5 | 短问题必须命中一半以上 |
| 1 | 0.75 | 单词查询极易误命中，从严 |

另有两条特殊规则：

- **显式序号查询**（`追问2`、`第3题`）：只保留该序号的分块，不参与常规打分排序
- **问答块高阈值**：带序号且**不属于任何编号小节**的分块（如纯文本资料里的 `【追问1】`），阈值提到 0.75，避免被泛问误召回；若它归属于某个编号小节（如 `3.3` 下的追问），则沿用常规阈值，这样「工作文件可以发到个人邮箱吗」这类自然提问也能问到

### 5.1 主题一致性校验

覆盖率只管「像不像」，管不了「是不是同一件事」。员工问「部门采购的审批流程」，在看不到采购制度时，财务文档的 `3.1 审批流程` 会凭 `审批 / 流程 / 部门` 三个词拿到 0.57 覆盖度，答出一段**答非所问**的内容。

因此加一道校验：把 query 的词分成**通用词**与**主题词**，要求候选分块至少命中一个主题词。

```
通用词：流程 审批 审核 签批 申请 规定 要求 办法 标准 条件 材料 时间
        部门 公司 员工 内容 相关 制度 管理 使用 处理 办理 提交 情况 问题 系统
主题词：其余全部（如「采购」「轮岗」「发票」「访客」…）
规则：主题词为空 → 不校验；否则候选必须命中至少 1 个主题词
```

校验在**候选阶段**执行，不参与打分。上述例子中，主题词是 `采购 / 门采`，财务 `3.1` 一个都不含 → 丢弃 → 正确拒答。

## 6. 编号小节聚合

分块按 `headingNumber` 分组，同一小节下的内容合并为**一条完整答案**：

```
### 1.1 Transformer 与 Self-Attention      ← 小节标题（答案标题）
    正文段落
    #### Q/K/V 的含义                      ← 无编号子标题，并入
    #### 计算流程
    【追问1】【追问2】【追问3】              ← 问答分组，并入
### 1.2 Token 与上下文窗口                  ← 另一个独立答案
```

合并时按 `(headingContext, label)` 去重，避免同一个子标题被重复带入。

**口径**：答案单元 = 分块「最近的带编号祖先」。两层编号文档（`### 1.1` + 无编号 `####`）下就是「1.1 一条、1.2 一条」；若文档出现三级编号（`1.1.1`），更深层编号会各自成条。

## 7. 排序、相对过滤与取用

```js
candidates.sort(score ↓, titleCoverage ↓, coverage ↓, passage 长度 ↓)

bestCoverage   = max(candidates.coverage)
siblingCoverage = bestCoverage * 0.8      // 相对门槛

// 逐条取用
跳过 coverage < siblingCoverage 的候选（显式序号查询与 exact 命中不受限）
按 (docId, 小节号) 去重；每个文档最多 2 条；总计最多 5 条
常规查询展示前 3 条；显式序号查询展示全部命中（最多 5 条）
```

排序是**四级比较**：总分（含标题权重）→ 标题覆盖度 → 正文覆盖度 → 分块长度。加第二排序键 `titleCoverage` 的意义在于：当两个候选总分打平时，标题命中更多的那条更可能是主题所在。

> 显式序号查询不截断，是因为「追问2」这类问法在每份文档里都有一条，若只显示 3 条，第 4 份文档的答案会被静默丢掉——离线评测的 O09 用例正是这么暴露出来的。

`siblingCoverage` 的作用是防止兄弟小节被顺带拖出：问「Token 与上下文窗口」时，`1.1` 因正文里出现「上下文信息」能拿到 0.6 覆盖度，而最佳命中是 1.0，0.6 < 0.8 → 丢弃。

> 注意：这个门槛**不能设绝对下限**。早期写成 `max(0.5, best×0.8)`，导致唯一命中项（覆盖度 0.375）也被滤掉，出现「年假要提前几天申请」拒答。离线评测把这个回归抓了出来。

## 8. 拒答判定

```js
if (!results.length || (target === null && results[0].coverage < 0.24)) → 拒答
```

- 显式序号查不到 → 「资料中没有找到序号 N 对应的问答」
- 常规查询无依据 → 「没有找到与「X」足够匹配的内容，为避免编造，不生成推测性答案」

## 9. 评测结论

`eval/run-eval.mjs` 现有 **118 条**用例，分 5 组：自然语言检索 52 · 同义改写 20 · 编号定位 10 · 无依据拒答 26 · 权限隔离 10。

### 第一轮：36 条 → 检索 68.4% → 100%

| 缺口 | 现象 | 修复 |
| --- | --- | --- |
| 小节标题不可检索 | 「发薪日是什么时候」拒答（关键词只在标题 `2.1 发薪日` 里） | 打分时把 `headingTitle` 并入可检索文本 |
| 追问内容问不到 | 「工作文件可以发到个人邮箱吗」拒答（答案在 `【追问1】` 里，被 0.75 阈值挡住） | 高阈值只对**无编号祖先**的问答块生效 |
| 相对过滤门槛过高 | 「年假要提前几天申请」拒答（唯一命中项 0.375 < 硬下限 0.5） | 去掉绝对下限，只保留 `best × 0.8` |

### 第二轮：扩到 118 条 → 93/118（78.8%）→ 118/118（100%）

扩充语料（新增财务报销 / 培训与职业发展 / 会议室与办公环境三份带编号小节的演示文档）后，又暴露并修复了 6 类缺口：

| 缺口 | 现象 | 修复 |
| --- | --- | --- |
| 疑问短语留噪声 | 「带教期是多长时间」拒答（`什么时候` 被切成 `时候`，残留 2-gram 稀释覆盖率） | 疑问短语整体删除，且删除顺序在单字虚词之前 |
| 纯功能字 2-gram | `可以` `需要` 等拉低覆盖率 | 两个字符都是功能字的 2-gram 直接丢弃 |
| 同义不同词 | 「口令多久需要更换一次」拒答（原文写的是「密码」） | 同义词归一化（§2.1） |
| 删虚字误伤实义词 | 「辞职后设备要归还吗」拒答（`归还`→`归`、`到场`→`场`） | 单字虚词表收紧，不再删 `到/还/对/为/有` |
| 跨主题误召回 | 「部门采购的审批流程」被财务「审批流程」小节接住 | 主题一致性校验（§5.1） |
| 序号查询被截断 | 「追问2」只显示 3 条，第 4 份文档的答案被静默丢掉 | 显式序号查询展示全部命中 |

> 每一步都是「先跑评测拿到失败明细 → 定位 → 改 → 复跑确认」，改动前后都有数字对比。中途也出现过回归——把 `哪家` 从疑问短语删掉后，「公司用的是哪家 ERP 系统」因分母变小而误召回——同样由评测拦下。

### 第三轮：标题权重建模 + LLM 重排 → 仍为 118/118

在前两轮把**召回**补齐后，第三轮转向**排序**（提升长文档下的 Top-1 精度）：

| 改动 | 说明 | 结果 |
| --- | --- | --- |
| 标题权重（§3.1） | 小节标题单独打分，按 0.5 权重并入总分，并作为第二排序键 | 118/118、浏览器错误 0（排序优化不改召回集合，无回归） |
| LLM 重排（[`生成层说明.md`](生成层说明.md) §8） | 可开关；重排只改顺序，失败静默回退 | 单独由 `eval/model-rerank-test.mjs` 验证 24/24 |

**一次真实回归（已修）**：最初把标题权重也加进了**显式序号分支**，并把 `headingNumber` 一并挂上候选对象，导致该候选被后面的聚合逻辑当成「编号小节」处理，而序号分支并不携带 `documentSections` → 解引用报错。表现为「编号定位 2/10、综合 110/118、浏览器错误 10」。修复方式是让序号分支保持原样（只加 `labelMatch.score * 0.15`，不携带 `headingNumber` / `titleCoverage`），复跑回到 118/118。

> 教训：**排序改动也必须全量复跑**。118 条里「编号定位」这 10 条专门覆盖了序号分支，正是它们把这次改动拦了下来。

## 10. 已知不足

- **同义词表靠人工维护**：目前 14 组，覆盖面有限；未收录的改写（如 `休假` vs `请假` 这类上下位关系）仍会漏召回。LLM 重排**解决不了召回不到**的问题——候选没进来，就无从重排
- **2-gram 噪声仍在**：跨词边界的双字（如「天申」）无法完全剔除，只能靠删疑问短语与功能字 gram 缓解
- **主题词表是硬编码的**：`GENERIC_TERMS` 靠人工枚举，换领域需要补充
- **标题权重是常数 0.5**：未做参数搜索，也未按标题层级（`1.1` vs `####`）区分权重
- **重排依赖外部模型**：会多一次网络往返，且模型排序未必优于词面打分；默认关闭，建议在自有语料上对比后再开
